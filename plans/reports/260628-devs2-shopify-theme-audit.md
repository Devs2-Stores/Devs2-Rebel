# Báo cáo audit theme Devs2 Shopify

## Tóm tắt

Theme `Devs2 Rebel` là một Shopify Online Store 2.0 theme thật, có cấu trúc section/template đầy đủ, design-system tokens rõ, cơ chế load CSS/JS theo route, nhiều snippet tái sử dụng, và nhiều hành vi storefront hiện đại.

Tuy nhiên, ở trạng thái working tree hiện tại, theme **chưa sẵn sàng release/deploy**.

Lý do chính: repo đang ở giữa quá trình migration/cleanup. Nhiều section bị prune/move, nhiều file active đang modified, quickview đang được đưa lại theo nhiều path, workflow tooling vẫn tham chiếu script đã xoá, và `shopify theme check` hiện đang fail với 3 lỗi.

Khuyến nghị: đóng băng feature work, làm một pass **release-readiness stabilization** trước, sau đó mới cleanup UX/performance/code-quality khi theme đã xanh.

## Điểm mạnh

- Cấu trúc OS2.0 đầy đủ: JSON templates, section groups, section/snippet composition.
- Kiến trúc global dễ hiểu: `themeConfig`, `ThemeUtils`, custom elements, `data-action` hooks.
- Design system tập trung: color schemes, tokens, spacing, typography, z-index, utility classes.
- Commerce surface khá mature: PDP, collection filters/sort, cart page/modal, quickview, wishlist, predictive/search surfaces.
- Có ý thức accessibility: skip link, labels, aria-live regions, focus trap helpers, semantic snippets.
- Có ý thức performance: load assets theo route, Swiper lazy loader, responsive images ở nhiều nơi.

## Findings quan trọng

### P0 — `theme check` fail vì ảnh thiếu width/height

`shopify theme check` báo 3 lỗi `ImgWidthAndHeight`:

- `sections/banner-hotspots.liquid:28`
- `sections/image-text-overlay.liquid:19`
- `sections/image-text-overlay.liquid:33`

Đây là các path dùng custom URL `<img>` có `alt` nhưng thiếu `width`/`height`. Điều này vi phạm rule trong `CONTEXT.md`: “`<img>` phải có `alt`, `width`, `height`”. Đồng thời gây rủi ro CLS.

Impact: theme chưa thể coi là xanh cho release. Cần sửa trước mọi deploy/release gate.

### P0 — GitHub Action gọi generator script đã bị xoá

`.github/workflows/generate-newsletter-image.yml:30` chạy:

```bash
python tools/generate_newsletter_image.py
```

Nhưng `tools/generate_newsletter_image.py` đang bị xoá trong diff hiện tại và thư mục `tools/` cũng vắng.

Impact: workflow GitHub sẽ fail khi manual dispatch hoặc khi trigger qua `.github/trigger-bfl-gen`. Hành vi tự động generate/upload newsletter popup image đang bị gãy.

### P0 — Quickview có thể hiển thị sai/stale product

Review tìm thấy nhiều lỗi correctness trong `assets/quickview-modal.js`:

- `assets/quickview-modal.js:237`: `loadProduct()` bỏ qua lần open product thứ hai nếu fetch product đầu tiên còn đang chạy. Người dùng mở quickview A rồi nhanh tay mở B; A có thể resolve vào modal trong khi state đang là B.
- `assets/quickview-modal.js:276`: fetch/init failure có thể để HTML product cũ trong modal thay vì thay bằng error state.
- `assets/quickview-modal.js:255`: product JSON fetch được nhưng không ghi vào `themeConfig.quickview.data` vì guard yêu cầu `themeConfig.quickview.data` đã tồn tại, trong khi `head-script` chỉ init `quickview: {}`.
- `assets/quickview-modal.js:417`: fallback selector tìm `product-variant-picker`, nhưng file untracked `templates/product.quickview.liquid` render `quickview-variant-picker`.

Impact: shopper có thể thấy/add nhầm sản phẩm hoặc variant/price/availability update bị gãy. Cần coi quickview là release blocker cho đến khi có một data/render contract canonical.

### P1 — Search modal smart fallback tham chiếu view đã xoá

`sections/main-search-smart.liquid` đã bị prune/delete, nhưng review phát hiện `assets/search-modal.js` vẫn build `/search?...&view=smart` khi predictive search URL bị thiếu/tắt.

Impact: fallback modal search có thể nhận sai markup hoặc 404, thiếu `#predictive-search-results`. Cần restore smart search view hoặc update/remove fallback path.

### P1 — Theme đang giữa quá trình prune/migration, chưa sạch

Working tree có nhiều section move/delete sang `backup/sections-pruned-2026-06-20/...`, nhiều templates/sections/assets modified, và quickview files untracked:

- `sections/main-search-quickview.liquid`
- `templates/product.quickview.liquid`

Impact: release risk cao cho đến khi ý định prune được chốt. Backup paths có thể không deploy lên Shopify, nhưng git state hiện chưa đủ coherent để coi là release candidate.

### P1 — `.theme-check.yml` còn stale ignore path

`.theme-check.yml:63-70` vẫn document/ignore `sections/main-search-smart.liquid`, hiện đã bị prune/move. Config cũng còn migration-era exceptions.

Impact: tool config bị drift. Theme-check tương lai có thể che lỗi thật hoặc gây nhiễu cho maintainer.

### P1 — Hotspot fallback product data hardcoded và dễ gãy

`sections/banner-hotspots.liquid:115-156` hardcode snowboard handles, prices, và CDN image URLs. Các fallback object dùng field `image`, trong khi `renderTooltipProduct()` đọc `product.featured_image` tại `sections/banner-hotspots.liquid:92`, nên fallback image không render theo path này.

Impact: demo/stale catalog data có thể leak ra storefront thật. Tooltip có thể hiển thị title/price/link cũ hoặc mất ảnh.

### P1 — Hotspot tooltip JS inject HTML với escaping yếu

`sections/banner-hotspots.liquid:90-94` build HTML string từ product JSON rồi gán `tip.innerHTML`. Product title/url/price được concat trực tiếp, chỉ có partial quote replacement trong `alt`.

Impact: product data thường đến từ Shopify, nhưng vẫn tạo bề mặt HTML injection không cần thiết và duplicate server-rendered product markup.

### P1 — Contact info render field rỗng và link xấu

`sections/page-contact.liquid:40-79` render address, phone, email, hours vô điều kiện. Nếu setting trống sẽ tạo visual card rỗng và `tel:` / `mailto:` target rỗng.

Impact: merchant có thể tạo bad keyboard targets, empty content, và contact UX yếu chỉ bằng cách để optional fields blank.

### P1 — Quickview implementation có nhiều entrypoint và logic trùng

Current status gồm deleted/moved `sections/main-search-quickview.liquid`, untracked `sections/main-search-quickview.liquid`, và untracked `templates/product.quickview.liquid`. Review cũng phát hiện duplicated quickview product markup và duplicated variant/image logic trong `assets/quickview-modal.js` so với `assets/quickview-variant-picker.js`.

Impact: quickview behavior dễ drift giữa search/product contexts. Fix tương lai có thể sửa một path nhưng bỏ sót path còn lại.

### P1 — Design-system radius settings không còn tôn trọng square controls

Review phát hiện `snippets/head-design-systems.liquid:115` và các biến radius liên quan đang dùng dạng `max({{ settings.buttons_radius }}px, var(--radius-control))` hoặc tương tự. `config/settings_data.json` hiện set button/input radii là `0`, nhưng CSS vẫn ép ít nhất fallback radius.

Impact: contract của merchant setting bị phá. Merchant chọn square controls trong theme settings nhưng storefront vẫn render rounded controls.

### P1 — Slideshow images có thể bị hardcode đè lên merchant settings

Review phát hiện logic homepage slideshow overwrite rendered slide images ở client-side bằng hardcoded CDN URLs. Nếu merchant đổi ảnh slide trong Theme Editor/templates, production vẫn có thể hiển thị hardcoded `devs2-hero-slide-*` assets.

Impact: admin settings không còn là source of truth. Ngoài ra có thể làm phí LCP request nếu Liquid eager-load một ảnh rồi JS swap sang ảnh khác.

### P2 — Custom image URL paths bypass Shopify image pipeline

`sections/banner-hotspots.liquid:28` và `sections/image-text-overlay.liquid:19/33` dùng raw `custom_image_url` strings. Các path này bypass Shopify `image_url | image_tag`, widths, responsive srcset, intrinsic dimensions.

Impact: mobile download nặng hơn, CLS risk, CDN behavior kém tin cậy. Nên ưu tiên `image_picker` fields trừ khi raw URL support là requirement bắt buộc.

### P2 — Page-contact sticky script quá phức tạp và dễ leak trong theme editor

`sections/page-contact.liquid:193-224` dùng resize listeners + `ResizeObserver` + height reads/writes để chọn sticky column.

Impact: repeated sync layout work khi resize/content change; không có cleanup trên section-unload trong theme editor; CSS sticky có thể thay thế phần lớn logic.

### P2 — Before/after slider có thể đọc layout tần suất cao

Review flag drag behavior trong `sections/before-after.liquid`: document-level mouse/touch listeners và `getBoundingClientRect()` trong lúc movement.

Impact: có thể gây jank trên mobile yếu và leak listeners trong theme editor. Nên dùng pointer events, cache rect, `requestAnimationFrame`, và cleanup khi unload section.

### P2 — CSS breakpoint lệch convention

Review tìm thấy `@media (max-width: 768px)` trong:

- `assets/page-contact.css:13`
- `assets/page-about.css:99`

Project rule trong `CONTEXT.md`: “Mobile-first: `min-width` breakpoints”.

Impact: maintainability/cascade drift. Không phải runtime blocker, nhưng nên normalize.

### P2 — `shop-social` vẫn emit empty wrapper, buộc callers duplicate check

`snippets/shop-social.liquid:3-66` tính `has_shop_social_links`, nhưng vẫn emit `<ul class="shop-social">` kể cả khi không có link. `sections/page-contact.liquid:89-99` phải duplicate social availability check để tránh empty markup.

Impact: thêm social network mới phải sửa nhiều nơi. Snippet nên tự quản empty-state.

### P3 — Còn orphaned/legacy asset và section references

Ví dụ:

- `assets/index.js:172` vẫn init `.section-flash-sale__swiper`, trong khi `sections/section-flash-sale.liquid` đã prune.
- `assets/index.css` vẫn chứa nhiều `.section-flash-sale` styles.
- `assets/banner-link.css` vẫn còn trong khi `sections/banner-link.liquid` đã prune.
- Locale strings vẫn còn map/popup-related entries sau khi nhiều related sections bị prune.

Impact: không nhất thiết broken vì CSS/JS unused có thể harmless, nhưng payload và maintenance surface vẫn lớn hơn cần thiết.

## Đánh giá kiến trúc

### Liquid / Templates

Tốt:
- JSON templates có cấu trúc nhất quán với `sections` + `order`.
- Active template section types resolve tới section files hiện có sau khi strip Shopify JSON header comments.
- Các surface chính đều có: index, product, collection, cart, blog/article, search, customer pages, wishlist, stores, FAQ.

Rủi ro:
- Nhiều templates đang modified trong dirty tree; không nên release trước khi revalidate trong Shopify preview.
- Raw HTML settings (`map_embed`) được cho phép trong contact/stores pages. Có thể intentional, nhưng security/product posture nên ghi nhận merchant-provided HTML risk.
- Một số content page-specific được hard-code bằng numbered settings thay vì repeatable blocks.

### Sections / Snippets

Tốt:
- Component model mạnh: product card, collection filters/sort, cart items/totals, variant pickers, modals, icons.
- Nhiều snippet có Liquid doc comments và parameter docs.
- Product/collection/cart architecture coherent.

Rủi ro:
- Quickview bị split qua quá nhiều entrypoint và JS initializer.
- Hotspot section trộn Liquid rendering, client-side hydration, hardcoded fallback catalog data, và raw URLs.
- Một số snippet load CSS/JS mỗi lần render; đây là pattern thường gặp trong Shopify, nhưng product-card render lặp có thể tạo duplicate stylesheet/script tags nếu chỉ dựa vào browser de-duping.

### JavaScript

Tốt:
- `assets/theme.js` tập trung `ThemeUtils`, routes, money formatting, cart updates, focus helpers.
- Custom elements dùng rộng rãi (`product-card`, `cart-modal`, `quickview-modal`, `search-modal`, `wishlist-manager`, etc.).
- `data-action` hooks giúp templates dễ đọc.

Rủi ro:
- Commerce UX phụ thuộc nhiều vào JS. Nếu JS fail, filters, quickview, cart modal, compare, wishlist, dynamic pagination degrade mạnh.
- Quickview hiện có race/stale-content/data-contract defects có thể hiển thị hoặc add sai product.
- Search modal fallback vẫn phụ thuộc smart-search view đã prune.
- Một số scripts dùng `innerHTML` với server/fetched HTML; nhiều trường hợp là Shopify section-rendering pattern chấp nhận được, nhưng hotspot tooltip escaping yếu.
- Theme editor unload cleanup chưa nhất quán cho inline scripts và document/window listeners.

### CSS / Design System

Tốt:
- Token system tập trung trong `snippets/head-design-systems.liquid`.
- Global utility classes cho heading/content/subheading/button sizes, image shapes, spacing, section padding.
- Color scheme classes được generate từ Shopify color schemes.

Rủi ro:
- Một số CSS mới dùng `max-width` breakpoints dù project document mobile-first pattern.
- CSS cho pruned sections vẫn còn trong active assets, tăng payload/maintenance.
- Page-specific CSS đang phình to; nên audit sau stabilization để tìm reusable patterns.
- Radius token logic có nguy cơ phá merchant setting contract khi setting là `0`.

### Performance

Tốt:
- CSS/JS load theo route, tránh load mọi template script globally.
- Swiper được dynamic load.
- Nhiều product images dùng responsive `image_url | image_tag` với widths/sizes.

Rủi ro:
- Raw custom image URLs bypass responsive transformations.
- Hero/slideshow image mutation có thể ảnh hưởng LCP và override merchant settings.
- Orphaned flash-sale/banner-link CSS/JS còn lại sau section pruning.
- High-frequency JS handlers cần profile trên mobile.

### Accessibility

Tốt:
- Skip-to-content link, aria labels, focus trap helpers, aria-live cart/toast areas.
- Nhiều controls có labels/titles.

Rủi ro:
- Missing image dimensions đã là theme-check errors.
- Empty contact links có thể tạo bad focus targets.
- Dynamic hotspot tooltip cần review kỹ focus/keyboard behavior.
- Một số raw custom image paths cần explicit alt/size rules.

### Tooling / CI / Deploy

Tốt:
- `.shopifyignore` exclude docs, refs, node_modules, git metadata, theme-check config khỏi Shopify deploy.
- `shopify theme check` có config và chạy được.

Rủi ro:
- GitHub Action tham chiếu script đã xoá.
- `.theme-check.yml` còn stale ignore cho section đã remove.
- Không có root README; `CONTEXT.md` tham chiếu `.agent/` files hiện không có.
- Dirty tree lớn khiến khó phân biệt intended migration với accidental regression.

## Các hướng remediation đã đánh giá

### Option A — Release-readiness trước

Chỉ fix blockers: theme-check errors, broken GitHub Action, stale theme-check ignores, contact blank-field guards, hotspot hardcoded fallback removal/safe fallback, quickview correctness, search fallback, validate previews.

Pros:
- Nhanh nhất để có baseline an toàn.
- Giảm release risk ngay.
- Scope nhỏ.

Cons:
- Để lại duplication/performance cleanup sâu cho vòng sau.

### Option B — Cleanup toàn bộ trước release

Fix blockers + quickview consolidation, responsive image refactor, prune orphaned CSS/JS/locales, contact/about simplification, JS cleanup.

Pros:
- Codebase sạch hơn, maintenance surface nhỏ hơn.
- Kiến trúc dài hạn tốt hơn.

Cons:
- Regression risk cao vì thay đổi nhiều storefront surfaces cùng lúc.
- Chậm hơn; khó validate toàn diện hơn.

### Option C — Revert prune, stabilize, rồi prune lại

Undo section pruning, đưa về green baseline, sau đó prune từng nhóm một.

Pros:
- An toàn nhất nếu ý định prune chưa chắc.
- Dễ isolate breakage.

Cons:
- Tốn thời gian nếu current prune phần lớn là intentional.
- Có thể tạm reintroduce dead sections.

## Khuyến nghị

Chọn **Option A** trước.

Lý do: rủi ro lớn nhất hiện tại không phải architecture quality, mà là release readiness. Theme có nền tốt, nhưng working tree hiện có hard blockers (`theme check` errors, quickview correctness, broken workflow, dirty prune state). Cần stabilize trước, rồi làm pass thứ hai cho quickview consolidation và payload cleanup.

8. Xoá hardcoded slideshow/hotspot fallback images/products hoặc chuyển sang merchant-configured products/images only.
9. Sửa contact blank field guards và bad empty links.

- `shopify theme check` pass với 0 errors; warnings được review/accept rõ.
- Git status có một intended diff coherent; không có runtime files untracked ngoài ý muốn.
- GitHub Action hoặc hoạt động, hoặc được intentionally remove/disable.
- Active JSON templates chỉ reference sections đang tồn tại.
- Homepage, PDP, collection, cart, search, quickview, contact/about render trong Shopify preview.
- Quickview không bao giờ show stale product sau failed/rapid opens và variant data update đúng.
- Search modal hoạt động khi exercise predictive-search fallback path.
- Không render empty contact rows/links khi settings blank.
- Không còn hardcoded demo snowboard data hoặc hardcoded hero image override trong live sections.
- Button/input setting `0` render square controls đúng.

Performance/accessibility gates:

- Above-fold images có intrinsic dimensions và loading/fetchpriority đúng.
- Không còn raw custom image URL path cho hero/lookbook trừ khi thật sự required.
- Mobile LCP không bị tệ hơn vì JS image swaps.
- Keyboard mở/đóng modals/quickview/search/cart được và return focus đúng.
